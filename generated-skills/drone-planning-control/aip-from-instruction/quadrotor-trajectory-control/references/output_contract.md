# Output Contract

For every command file (e.g. `commands/001.txt`), write to
`/root/results/<id>/`. The id is the command file's basename without
extension.

## Files

### `metrics_3d.json`
Exact schema:
```json
{
  "mode": "takeoff",
  "RiseTime": 1.23,
  "SettlingTime": 2.45,
  "Overshoot_pct": 3.1,
  "SteadyStateError": 0.01
}
```
- `mode`: one of `"takeoff" | "hover" | "land" | "fly"`.
- All numeric fields are floats in SI (seconds, meters, percent).
- Settling computed with `settling_threshold = 0.02`.
- Use `scripts/metrics.py::compute_metrics(planned, actual, dt, mode)`.

### `tuning_results.json`
Exact schema:
```json
{
  "kp_pos": [4.0, 4.0, 8.0],
  "ki_pos": [0.0, 0.0, 0.0],
  "kd_pos": [3.0, 3.0, 5.0],
  "kp_att": [200.0, 200.0, 80.0],
  "ki_att": [0.0, 0.0, 0.0],
  "kd_att": [20.0, 20.0, 10.0]
}
```
- Each value is a list of exactly 3 floats `[x, y, z]` (or
  `[roll, pitch, yaw]` for attitude).
- Use `scripts/tune_gains.py::gains_to_dict(gains)`.

### `planned_trajectory.npy` / `actual_trajectory.npy`
- Shape: `(15, max_iter)` numpy float array.
- `max_iter = ceil(T_used / dt)` (use the same `dt` for both files).
- Row layout, identical for both files:
  - rows 0:3 → position `[x, y, z]`
  - rows 3:6 → velocity `[vx, vy, vz]`
  - rows 6:9 → orientation `[phi, theta, psi]`
  - rows 9:12 → angular velocity `[p, q, r]`
  - rows 12:15 → acceleration `[ax, ay, az]`
- Planned trajectory's rows 6:9 and 9:12 may be all-zero (the planner
  doesn't prescribe attitude). The controller derives `phi_des` /
  `theta_des` from the desired thrust direction at runtime.

### `plots/`
Three PNG files generated by `scripts/plot_results.py::write_plots()`:
- `desired_vs_actual.png` — planned vs actual position per axis.
- `errors.png` — per-axis error and Euclidean error vs time; include the
  0.05 m success-criterion line.
- `cumulative_errors.png` — integrated |error| vs time per axis and
  Euclidean.

## Success criteria (per command)
All four must hold:
1. `SteadyStateError < 0.05 m`
2. `Overshoot_pct < 5`
3. `max(|planned[12+i, :]|) ≤ accel_limit_*` for each axis (i = 0,1
   against `accel_limit_horiz`; i = 2 against `accel_limit_up` when
   accel positive, `accel_limit_down` when negative).
4. `max_k ‖actual[0:3, k] - planned[0:3, k]‖ < 0.05 m`.

If a command fails any of these, write the bundle anyway (don't abort)
and report it so the agent can re-tune. The evaluator inspects the
output regardless of pass/fail.
