# Provenance

This AIP skill — `financial-model-qa` — is compiled from two curated Anthropic Agent
Skills (verbatim copies kept under this directory) plus the task's container Dockerfile
that pins the available runtime.

| Source                                        | Role                                                                                      |
|----------------------------------------------- |------------------------------------------------------------------------------------------ |
| `pdf/SKILL.md` + `pdf/references/` + `pdf/scripts/` | Toolkit for reading PDFs — specifically `pypdf` text extraction, which the task container has installed. |
| `xlsx/SKILL.md` + `xlsx/recalc.py`             | Toolkit for reading/analyzing xlsx — openpyxl + pandas usage, color-code / unit / formula conventions, formula-error awareness. |
| `Dockerfile`                                   | Pins the runtime: Ubuntu 24.04, Python 3, `pandas==2.2.3`, `openpyxl==3.1.5`, `pypdf==5.1.0`. `/root/data.xlsx` and `/root/background.pdf` are the two inputs. |

The compiled skill answers one shape of task: *given a financial model packaged as an
Excel workbook plus a background PDF, answer a question about it*. The curated skills
are general-purpose; this skill carves them down to the read-only Q&A path the task
needs, and keeps the specialized knowledge an agent needs to interpret a financial
model correctly (color coding, units, formula conventions, source citations).

## Step-kind choices

Three steps: one `execution`, one `client_task`, one `end`. No router — the workflow
has a single straight path.

- **`extract` (execution)** — reading a workbook and a PDF is deterministic code over
  three structured inputs (`question`, `xlsx_path`, `pdf_path`). It needs the libraries
  the Dockerfile provides and should be fast; dumping a sparse workbook as structured
  JSON is exactly the "numeric calculations / lookup tables / validation" lane a script
  is for. The script emits every non-empty cell with value + formula + number format +
  comment so a downstream decision wouldn't lose information by rounding to a label.
- **`answer` (client_task)** — the answer is agent-generated text (grounded reasoning,
  not a lookup). We considered a `decision` step to classify the question (lookup vs
  derived vs narrative) with router branches to specialized downstream steps, but every
  branch would funnel into the same client_task to generate prose, so the router added
  structure without changing behavior. Keeping it one client_task matches the Best
  Practices guidance: don't fall back to a client task when a script or decision could
  do the work, but *do* use a client task when the output must be generated by the
  agent itself.
- **`end`** — publishes the final `{question, answer, justification}` shape.

## Deliberately dropped source content

Rules, conditions, thresholds, lookups, branching, and the context needed to apply them
are *never* deliberately dropped. The items below are deliberate drops: background,
rationale, or workflows outside this skill's scope (writing/editing/forms).

### From `pdf/SKILL.md`

- **Merging / splitting / rotating / encrypting PDFs** — write operations; this skill
  only reads. Not actionable for financial-model Q&A.
- **PDF form filling (and the whole `forms.md` + `scripts/fill_*.py` / `check_*.py` /
  `extract_form_field_info.py` body)** — form-filling is a different workflow entirely.
  Kept verbatim under `source/pdf/` for provenance; not surfaced in the compiled body.
- **Creating PDFs with `reportlab`** — write-side; not in scope.
- **`pdftotext` / `qpdf` / `pdftk` / `pdfimages` CLI examples** — not available in the
  task container's Dockerfile (which installs `pypdf` only). Would be dead advice if
  surfaced to an agent whose container doesn't carry them.
- **OCR via `pytesseract` + `pdf2image`** — not installed in the task container; the
  skill's `do_not_use_when` names scanned PDFs as out of scope, and
  `references/pdf-reading.md` notes the fallback.
- **Watermarking / password protection / password removal** — write-side.
- **Convert PDF to images, bounding-box checks, validation image creation** — form- and
  rendering-side utilities. Not in scope.
- **`pdfplumber` as the default extractor** — the task container has `pypdf`, not
  `pdfplumber`. The compiled skill uses `pypdf` and mentions `pdfplumber` only as an
  "if available" fallback in `references/pdf-reading.md`.

### From `pdf/references/forms.md` and `reference.md`

- Entire bodies dropped — not relevant to the Q&A path. Kept verbatim under
  `source/pdf/references/` for provenance.

### From `xlsx/SKILL.md`

- **Zero formula errors / editing templates / preserving template formatting** —
  write-side quality bars. The compiled skill reads only; it does mention how to
  recognize `#REF!` / `#DIV/0!` / `#VALUE!` / `#N/A` / `#NAME?` because a reader has to
  interpret those (see `references/financial-conventions.md`).
- **Color coding standards, number formatting standards, formula construction rules,
  source documentation for hardcodes** — carried into `references/financial-conventions.md`
  under the "load when the question hinges on units / color coding / conventions / source
  citations" trigger. These are *reading* concerns in a QA context, not writing concerns.
- **`recalc.py` and the LibreOffice recalculation workflow** — the task container does
  not install LibreOffice (Dockerfile lists only `python3 pip pandas openpyxl pypdf`).
  Running it inside the task container would fail. The compiled skill handles missing
  cached values by surfacing them in `xlsx_data.notes` and instructing the agent to
  compute from the formula chain instead. `recalc.py` is kept under `source/xlsx/` for
  provenance.
- **"Formula Verification Checklist"** — write-side quality checks (test formulas,
  check division by zero, verify dependencies). The reading-side parts (column mapping,
  row offset, cross-sheet reference format, NaN handling) are carried into
  `references/xlsx-reading.md`.
- **Creating new Excel files with openpyxl, editing existing files with openpyxl,
  pandas writing** — write-side; out of scope.
- **Code style guidelines** — authoring guidance for scripts; the compiled skill's own
  `scripts/extract_sources.py` already follows the "minimal, concise" rule.

### From `pdf/references/LICENSE.txt` and `xlsx/LICENSE.txt`

- Kept verbatim under `source/`. Not surfaced in the body — license text is governance
  metadata, not procedural content.

### From the Dockerfile

- Package pins (`pandas==2.2.3`, `openpyxl==3.1.5`, `pypdf==5.1.0`) and the input
