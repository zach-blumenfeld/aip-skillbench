# d3-visualization: provenance and compilation notes

## Provenance
Compiled from the curated Agent Skill `d3js-visualization` (copied verbatim here):
- `SKILL.md`: determinism/offline rules, inputs/outputs, project layout, tooltip/click/conditional-interactivity patterns.
- `scripts/bubble_chart_example.js`: force-clustered bubble chart (sqrt radius, category colors, uniform radius for missing values, ETF tooltip exclusion, click → table highlight).
- `scripts/interactive_table_example.js`: sortable table linked to a chart, K/M/B/T formatting, row selection CSS.
- `scripts/tooltip_handler.js`: reusable TooltipHandler (shouldShow, formatContent, move, attach) + CSS.
- `scripts/check_tooltip.js`: console checks for tooltip element / `.visible` / content.

Environment facts used (from the task's environment, not from the skill): the container is Ubuntu 24.04 with
python3, node/npm, and Python Playwright + Chromium; the inputs are pandas-exported CSVs
(`stock-descriptions.csv`: leading unnamed index column, 50 rows, `ticker`, `sector`, `full name`,
`marketCap`, ...; ETF rows have empty marketCap/country/website) and a folder of per-ticker price CSVs in
two layouts (stocks: `,Date,Low,Open,Volume,High,Close,Adjusted Close`; ETFs, lower-case file names:
`,Date,Open,High,Low,Close,Volume,OpenInt`).

## Intent
Turn local data into a D3 page that is offline (pinned, vendored D3), deterministic (identical SVG on every
load), and verified. The most specialized pattern in the sources (clustered bubbles + linked table + conditional
tooltips) is generated by a script from a field-mapping spec; everything else is hand-written under the same
rules. Every page is audited against the task and checked in headless Chromium before the run ends.

## Step-kind choices
| Step | Kind | Why |
|---|---|---|
| profile-data | execution | Column kinds, missing counts, categories with all-missing fields, file-name/key case matching are deterministic facts; the spec and decision steps need them in the state instead of guessing. |
| classify-request | decision (choice) | Fixed answer space (generator can build it / hand-write it); judged from the task text. Threshold 0.7 because a wrong route costs a whole branch. |
| route-family / route-build / route-verify | router | Pure branching on a typed value. |
| write-bubble-spec | client_task | Mapping free-text requirements (paths, header labels, exclusions) onto spec fields needs reading the task; output is structured JSON validated by the next script. |
| build-bubble-page | execution | Spec validation against real columns, D3 vendoring, data copy, embedding, and the page code itself are deterministic and fragile; generating them from templates removes per-run drift. Errors loop back to the spec step. |
| plan-custom-page / author-custom-page | client_task | Arbitrary chart types need generated code; rules are carried in templates + `references/d3-rules.md`. |
| vendor-d3 | execution | Getting a pinned bundle (bundled copy → node_modules → npm pack → download) is mechanical. |
| audit-requirements | client_task | Line-by-line comparison of the task text against the output is a judgment/synthesis; it may also edit files for requirements the generator does not express. |
| verify-page | execution | Offline/determinism/interaction checks are scriptable (static scan + Playwright); failures loop through fix-page. |
| fix-page | client_task | Repairs are code edits. |

## Deliberate drops and deviations
- **D3 default pin 7.9.0 vs. "D3.js (v6)" in the description.** The sources conflict. Rule kept: use the version the task names; generator default is v6 (matches the skill's own description); both 6.7.0 and 7.9.0 are bundled. Documented in d3-rules.
- **`vendor/` beside `dist/` in the recommended layout.** Nested as `dist/vendor/` by default so the output folder is self-contained; the verifier serves the common parent of all referenced files, so the original sibling layout still verifies (fresh-agent test found the earlier 404).
- **Tooltip `transition: opacity 0.2s`.** Dropped: conflicts with the non-negotiable "no transitions" rule and makes the visible state time-dependent for checkers. Noted in CSS and d3-rules.
- **"Or bundling with a lockfile".** Dropped as an alternative to vendoring; vendoring a single pinned file is simpler and always offline.
- **Live `simulation.on('tick')` animation and `forceCenter` in the bubble example.** Replaced by a fixed tick loop (source's own determinism rule); per-cluster forceX/forceY already centre the layout. A bounds force and a packing-density cap were added so "no overlap" holds for any data.
- **`d3.csv('/data/stocks.csv')` absolute URL in the example.** Replaced: data is embedded in visualization.js (renders from file:// where fetch is blocked) with a relative d3.csv fallback; raw files are still copied when the task asks.
- **Table sort treating missing numbers as 0.** Changed to "missing last" so ETFs without market cap don't sort as the smallest companies.
- **Tooltip `name || 'N/A'`.** Missing values render as the table's `missing_text` (default "-") for consistency.
- **Two `formatNumber` variants** (tooltip_handler's returned "-" for 0). The table example's version (handles 0 and negatives) is the one kept.
- **Example usage functions `example1..4` in tooltip_handler.js and the CSS-injection snippet in the table example.** Not procedural; kept verbatim in `references/examples/` for the hand-written path.
- **`.tooltip-header` / `.tooltip-body` CSS classes.** Only used by example3; kept in the reference copy, not in generated pages.
