## Intent

One procedure that takes a task statement and a workbook path and leaves the workbook with a
score sheet: the copied input columns, a `TotalKg` formula and a score formula per lifter, cached
values from a real recalculation, and an independent check that every value is right.

## Component-kind choices

| Step | Kind | Why |
|---|---|---|
| `identify-score` | decision | Which score (fixed label set) and how many decimals (ordered scale 0-6) are judgments over free text with a closed answer space. `decimals` as a score question collapses to its level number, which is exactly the integer the script needs. Thresholds are high because a wrong score or precision silently produces a wrong sheet. |
| `by-score-system` | router | Dots/Wilks/IPF GL have complete parameters in the source and are scripted; anything else cannot be scripted from the source. |
| `build-score-sheet` | execution | Column selection, ordering, formula text, coefficients, clamps, sex mapping, rounding, recalculation and verification are deterministic. One script (fewer files) does write + recalc + verify so the check always runs. Coefficients live in `assets/coefficients.json` (lookup table, injected as an asset). |
| `by-check` | router | Branches on the script's `recalc_status`. |
| `fix-workbook` | client_task | Repairing a failed recalc (finding an engine, fixing an error cell) needs the agent's own actions on the machine. |
| `manual-score-sheet` | client_task | Glossbrenner etc. must be generated by the agent; the source lacks Schwartz/Malone constants, so the template forbids inventing them. |
| `end` | end | Result is the edited workbook (`workbook_path`) and `score_system`; keys produced on only one branch are not end inputs. |

Design decisions worth knowing:

- Column rule: copy `Name` plus exactly the columns the score reads (Dots/Wilks: Sex, BodyweightKg,
  Best3SquatKg, Best3BenchKg, Best3DeadliftKg; IPF GL adds Event, Equipment), ordered as in the
  data sheet, with the data sheet's header text. An existing `TotalKg` in the data is not copied;
  the task requires appending a computed one.
- Formulas: `TotalKg = ROUND(SUM(S,B,D), n)`; score `= IF(OR(N(bw)<=0, N(total)<=0), 0, ROUND(total*500/IF(sex="F", poly_women(clamp), poly_men(clamp)), n))`.
  `N()` keeps blanks/text from raising #VALUE!/#DIV/0! and matches the source's "zero bodyweight or
  total -> 0" rule. `IF(sex="F", women, men)` encodes "M and Mx use men's". No `LET` (LibreOffice 24.2
  on Ubuntu 24.04 may lack it).
- Precision: "keep 3 digits precision" is read as rounding TotalKg and the score to 3 decimals with
  Excel `ROUND` (half away from zero; the Python check uses the same rounding).
- Numbers stored as text in the numeric columns are copied as numbers (else `N()` would score them 0)
  and reported as anomalies. Negative lifts (OPL failed-attempt markers) and blanks are summed as-is
  and reported, because the task defines TotalKg as the sum of the lifts.
- Recalculation: LibreOffice `--convert-to xlsx` with a throwaway profile first (no macro install,
  no profile lock), then the xlsx skill's `recalc.py` macro, then gnumeric `ssconvert --recalc`. The
  recalculated file replaces the original only if every score cell has a cached value. The original
  is backed up to a temp dir (never next to the data, so no stray files appear in the task folder).
- `requires` lists python 3.10 and openpyxl (all the script imports outside the stdlib). LibreOffice
  and gnumeric are called only if found on PATH; the script still writes correct formulas without
  them and reports `not_recalculated`, which routes to `fix-workbook`. They are therefore described
  in `compatibility`, not listed as hard `tools` (which would block a run on a gnumeric-only machine).
- `scripts/recalc.py` is mirrored verbatim from the xlsx skill: the build script imports it as a
  fallback, and the fix/manual templates tell the agent to run it.

## Functional test record (2026-10-20)

- Container: the task Dockerfile built locally (Ubuntu 24.04, Python 3.12.3, LibreOffice). Script
  run there exactly as the runtime launches it, on the real `openipf.xlsx`: 20 rows, columns Name,
  Sex, BodyweightKg, Best3SquatKg, Best3BenchKg, Best3DeadliftKg, TotalKg, Dots; LibreOffice
  recalc; `verified`, max diff 0; Data sheet values and types unchanged after the round-trip.
- Bug found and fixed: the task's empty "Dots" sheet has dimension A1:A1, so openpyxl `append()`
  started at row 2; the script now writes by explicit coordinates.
- Edge-case workbook (Mx, blank/text/out-of-clamp bodyweights, negative/blank lifts, existing
  TotalKg column, junk in Dots, bench-only and BD events, Single-ply) for dots, wilks and
  ipf_goodlift: all `verified`, zero formula errors, anomalies reported.
- `aip run` (local, LibreOffice reached through a scratch shim into the container): dots ->
  verified -> end; dots with no engine -> not_recalculated -> fix-workbook -> end; Glossbrenner ->
  other -> manual-score-sheet -> end (TotalKg built, points column reported as blocked on missing
  Schwartz/Malone constants); wilks and ipf_goodlift -> verified -> end. The `formula_errors` and
  `mismatch` values of `by-check` route to the same fix-workbook step; no real input produced them.
