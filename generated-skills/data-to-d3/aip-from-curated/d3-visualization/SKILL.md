# AIP runtime — format 0.5a1

You are executing an Agent Instruction Protocol (AIP) procedure: the fenced YAML block in this skill's `SKILL.md`. AIP is a protocol for cheaply, quickly, and accurately executing multi-step tasks as a graph of typed steps. You drive the run and execute every step yourself, following the semantics below.

Critical terminology:

- **Client**: you, the agent running this procedure; the `client_task` step kind is named for it. You supply each step's input, run its script, answer its questions by your own judgment, perform its task, follow its router, and make the final call at every step.
- **State**: the JSON object a step receives. Each step declares its required keys as `inputs`; extra keys pass through.
- **Step kinds**: `execution` runs a script, `decision` asks typed questions about the state, `client_task` hands work to you, `router` branches on a value in the state, `end` declares the final state's shape.

## Execution

The state is one JSON object. It starts as the start step's `inputs` and flows along `inputs_to`; each step's output is merged over it, so keys accumulate and extra keys pass through untouched. A step runs only if the state holds every key it declares in `inputs`, with the declared types; check that before each step. You may change the state before any step runs; you have the final say at every step.

- **`execution`**: run `script` with one JSON object on stdin, `{"currentState": <state>, "assets": {<file stem>: <content>}, "expects": <the next step's inputs>}`. The script writes one JSON object to stdout; merge it over the state.
- **`decision`**: answer each question against the state. Each answer collapses to one value under its question name and is merged over the state: a noul to `true`/`false`, a choice to its label, a score to its level number. `thresholds` name the questions where an uncertain answer matters most; when your answer to one is a close call, reconsider it before continuing.
- **`client_task`**: render `template` with `{key}` from the state, `{assets[stem]}` for its assets, and `{meta.name}` for the skill name. Perform the task, loading `references` if their descriptions apply, and produce the next step's `inputs`; merge them over the state.
- **`router`**: read the state's `branch_on` key and continue at `branches[value]`. A value with no branch is an error.
- **`end`**: the state must hold `end`'s `inputs`. That state is the procedure's result.

```yaml
purpose: >
  Turn local data files (CSV/TSV/JSON) into a deterministic, offline D3.js web page that a
  checker can diff or hash: pinned, locally vendored D3 (bundled 6.7.0 / 7.9.0, never a CDN),
  fixed size and viewBox, sorted domains, no randomness or transitions, force layouts run for a
  fixed number of ticks. Clustered bubble charts with a linked sortable table, conditional
  tooltips, a legend, and optional per-entity time series are generated by a script from a
  field-mapping spec; any other chart is hand-written under the same rules. Every page is then
  audited against the task line by line and verified in headless Chromium (render, identical
  SVG across loads, mark counts, overlap/bounds, tooltip show/hide/exclusion, click linking).

trigger_when:
  - A task asks for a chart, plot, graph, or data visualization built with D3.js (any version).
  - Bar, line, scatter, area, histogram, box, violin, heatmap, bubble, timeline, small-multiple, or faceted charts from local data files.
  - Axis ticks, scales, legends, tooltips, click highlighting, or a chart linked to a data table.
  - Data-driven SVG or a standalone HTML visualization for a report or web page, especially one that must work offline or be deterministic.

do_not_use_when:
  - The user only needs a quick table or summary; use a spreadsheet or plain markdown instead of D3.
  - The task requires a different plotting library (matplotlib, plotly, Vega) rather than D3.

steps:
  - name: profile-data
    kind: execution
    description: Profile every data file and folder (columns, kinds, missing counts, category values, categories with all-missing fields, per-entity file folders and how their names match a key column).
    inputs:
      - name: task_request
        type: string
        description: The task's instructions, verbatim, including every path, column, and interaction it names.
      - name: data_paths
        type: list[*]
        description: Absolute paths of the input data files and folders (relative paths would resolve against the skill's scripts/ folder).
      - name: output_dir
        type: string
        description: Absolute folder the task wants the page in; when the task names none, use dist/ under the current working directory.
    script: scripts/profile_data.py
    inputs_to: classify-request

  - name: classify-request
    kind: decision
    description: Decide whether the request is a clustered bubble chart the generator builds or a chart to hand-write.
    inputs:
      - name: task_request
        type: string
      - name: data_profile
        type: object
    questions:
      chart_family:
        type: choice
        instructions: >
          Which kind of D3 page does the task ask for? Judge the marks and their positioning, not
          the extras: a legend, tooltips, click highlighting, a linked data table, and a
          per-entity time series shown on selection are all supported by the bubble generator.
        criteria:
          clustered-bubble: One circle per entity (row), sized by a numeric field and colored/grouped by a category, positioned by a force/packing layout rather than axes; optionally with a linked table, tooltips, legend, labels.
          other: Any chart with positional axes or another mark type - bar, line, area, scatter (including bubbles placed on x/y axes), histogram, box, violin, heatmap, map, network, timeline, small multiples - or a bubble chart plus extra views the generator cannot produce.
    thresholds:
      chart_family: 0.7
    inputs_to: route-family

  - name: route-family
    kind: router
    description: Generated bubble page or hand-written chart.
    branch_on: chart_family
    branches:
      clustered-bubble: write-bubble-spec
      other: plan-custom-page

  - name: write-bubble-spec
    kind: client_task
    description: Map the task's wording onto the generator's spec (paths, D3 version, key, size/color/cluster fields, tooltip fields and exclusions, table columns and formats, linking, optional series).
    inputs:
      - name: task_request
        type: string
      - name: data_profile
        type: object
      - name: output_dir
        type: string
      - name: build_report
        type: object
        description: Empty on the first pass; the generator's errors on a retry.
    template: assets/bubble-spec.md
    assets:
      - assets/bubble-spec-example.json
    inputs_to: build-bubble-page

  - name: build-bubble-page
    kind: execution
    description: Validate the spec against the data, vendor pinned D3, copy the data, and write index.html, visualization.js (data embedded, fixed-tick force layout, conditional tooltips, legend, linked sortable table), and style.css.
    inputs:
      - name: viz_spec
        type: object
      - name: data_profile
        type: object
    script: scripts/build_bubble_page.py
    assets:
      - assets/page-template.html
      - assets/viz-template.js
      - assets/style-template.css
    timeout: 300
    inputs_to: route-build

  - name: route-build
    kind: router
    description: Spec errors go back to the spec step with the build report; a clean build goes to the audit.
    branch_on: build_status
    branches:
      ok: audit-requirements
      error: write-bubble-spec

  - name: plan-custom-page
    kind: client_task
    description: Choose chart type, encodings, dimensions, file layout, D3 version, and interactions for a hand-written page; write the manifest the verifier will test.
    inputs:
      - name: task_request
        type: string
      - name: data_profile
        type: object
      - name: output_dir
        type: string
    template: assets/custom-plan.md
    references:
      - path: references/d3-rules.md
        description: Determinism, offline, file rules, default project layout (dist/, vendor/), and tooltip/click/table/bubble patterns. Load before planning file paths or interactions.
    inputs_to: vendor-d3

  - name: vendor-d3
    kind: execution
    description: Write the pinned D3 bundle to page_manifest.d3_path (bundled copy first, then node_modules, npm pack, download).
    inputs:
      - name: page_manifest
        type: object
    script: scripts/vendor_d3.py
    timeout: 300
    inputs_to: author-custom-page

  - name: author-custom-page
    kind: client_task
    description: Hand-write the HTML/JS/CSS for the planned chart under the determinism and offline rules.
    inputs:
      - name: task_request
        type: string
      - name: chart_plan
        type: object
      - name: page_manifest
        type: object
      - name: data_profile
        type: object
      - name: d3_vendor_source
        type: string
    template: assets/custom-author.md
    references:
      - path: references/d3-rules.md
        description: Full rule set and code patterns for tooltips (.visible class, pointer-events none), click highlighting, linked tables, number formatting, bubble scales and force clustering. Load before writing code.
      - path: references/examples/bubble_chart_example.js
        description: Force-clustered bubble chart with sqrt radius scale, category colors, uniform radius for missing values, tooltip exclusion. Load for force or bubble layouts.
      - path: references/examples/interactive_table_example.js
        description: Sortable table linked to a chart, K/M/B/T number formatting, row selection classes and CSS. Load when the page has a table.
      - path: references/examples/tooltip_handler.js
        description: Reusable TooltipHandler class (shouldShow filter, formatContent, attach) and its CSS. Load for multiple or conditional tooltips.
      - path: references/examples/check_tooltip.js
        description: Browser-console checks for the tooltip element, its .visible class, and content. Load when debugging a tooltip.
    inputs_to: audit-requirements

  - name: audit-requirements
    kind: client_task
    description: Check the generated files against every requirement in the task and edit them to close gaps.
    inputs:
      - name: task_request
        type: string
      - name: page_manifest
        type: object
    template: assets/audit-requirements.md
    references:
      - path: references/d3-rules.md
        description: Rules and patterns to follow when editing the generated page (determinism, offline D3, tooltip/click/table code).
    inputs_to: verify-page

  - name: verify-page
    kind: execution
    description: Static checks (local refs only, D3 version, script order, no randomness, LF, tooltip CSS) and headless-Chromium checks (no errors, identical SVG over file:// and http loads, counts, overlap/bounds, tooltip show/hide/exclusion, bubble<->row linking); exports SVG/PNG when requested.
    inputs:
      - name: page_manifest
        type: object
    script: scripts/verify_page.py
    timeout: 300
    inputs_to: route-verify

  - name: route-verify
    kind: router
    description: Pass ends the run; any failure goes to the fix step and back to verification.
    branch_on: verify_status
    branches:
      pass: end
      fail: fix-page

  - name: fix-page
    kind: client_task
    description: Fix every verifier failure in the generated files, then re-verify.
    inputs:
      - name: task_request
        type: string
      - name: verification
        type: object
      - name: page_manifest
        type: object
    template: assets/fix-page.md
    references:
      - path: references/d3-rules.md
        description: Rules and patterns to apply when fixing determinism, offline, tooltip, overlap, or linking failures.
    inputs_to: verify-page

  - name: end
    kind: end
    description: The written page, the requirement audit, and a passing verification.
    inputs:
      - name: page_manifest
        type: object
        description: Paths of every written file and the expectations that were verified.
      - name: requirement_check
        type: list[*]
        description: Each task requirement with status met/fixed/not-applicable and where it is satisfied.
      - name: verify_status
        type: string
      - name: verification
        type: object

anti_patterns:
  - Loading D3 from a CDN or leaving the version unpinned; the page must run offline with the bundled/vendored file the task names (e.g. js/d3.v6.min.js).
  - Fetching data with d3.csv when the page will be opened from file://; Chromium blocks it and the chart renders empty. Embed the data (the generator does) and still copy the raw files when asked.
  - Letting a force simulation animate on 'tick' or seeding positions randomly; run a fixed number of ticks from deterministic positions, then draw once.
  - Hiding tooltips with display:none or animating them with a transition; toggle a .visible class over opacity with pointer-events none, and put pointer-events none on text labels over marks.
  - Showing a tooltip for rows the task excludes (e.g. ETFs with no market cap/country/website); test the exclusion rule in the mouseover handler.
  - Dropping rows whose size value is missing; they still get a bubble with a uniform radius and a table row with "-".
  - Matching per-entity files by exact case; ETF files are lower-case (spy.csv) while keys are upper-case (SPY), and the two file families have different column orders (Adjusted Close exists only for stocks).
  - Renaming columns the task or data uses ("full name", "marketCap"); read them exactly as the profile reports them.
  - Treating the leading unnamed column of pandas-exported CSVs as data; it is a row index.
```
